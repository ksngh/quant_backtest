# FVG Retest V2 Research Protocol

FVG retest v2 remains an offline research candidate. This protocol defines how to evaluate it without selecting parameters from a narrow in-sample winner.

Safety boundary:

- No live trading, paper promotion, testnet promotion, exchange order/account endpoints, signed requests, API keys, or `.env` behavior.
- All outputs are saved-run or local backtest research metadata.
- Losing, no-fill, failed, and high-cost variants must remain in the evidence package.

## Required Data Splits

Predeclare UTC candle ranges before running a study:

- Train: indicator warmup and pattern context only.
- Validation/WFO test folds: rolling out-of-sample windows generated by `WalkForwardConfig`.
- Final test: separate untouched OOS segment after parameter-family selection.
- Locked holdout: final untouched segment; do not retune after reading it.

If holdout fails, open a new research cycle with a new predeclared search space. Do not relabel the failed holdout as validation data.

## Predeclared Parameter Ranges

The code helper `default_fvg_retest_v2_parameter_grid()` declares the default exploratory grid:

- `detector.use_multitimeframe_trend_score`: `false`, `true`
- `detector.use_fibonacci_confluence`: `false`, `true`
- `risk.require_liquidity_target`: `false`
- `entry.mode`: `limit_at_pattern_midpoint`
- `entry.trigger`: `touch`, `touch_and_reaction_close`
- `risk.stop_mode`: `fvg_boundary_atr_buffer`, `wider_of_fvg_and_swing`
- `cost.profile`: `conservative_crypto_1m`

Every run must validate the declaration with `validate_fvg_retest_v2_parameter_declaration(...)`. The validator rejects missing required paths, empty ranges, excessive combinations, and zero-cost-only evidence. Zero-cost variants are allowed only as debugging rows when at least one realistic non-zero cost profile is also present.

## Runnable Command Set

Validate a bounded grid without executing variants:

```bash
python -m quant_bitcoin.backtesting.pattern_parameter_grid_cli \
  --csv candles.csv \
  --pattern FAIR_VALUE_GAP \
  --dry-run \
  --param entry.mode=limit_at_pattern_midpoint \
  --param entry.trigger=touch,touch_and_reaction_close \
  --param risk.stop_mode=fvg_boundary_atr_buffer,wider_of_fvg_and_swing \
  --param cost.profile=conservative_crypto_1m \
  --max-combinations 8
```

Run fixed-parameter WFO for the selected predeclared candidate:

```bash
python -m quant_bitcoin.backtesting.walk_forward_cli \
  --csv candles.csv \
  --train-window 30D \
  --test-window 7D \
  --step-size 7D \
  --strategy pattern \
  --pattern FAIR_VALUE_GAP \
  --entry-mode LIMIT_AT_PATTERN_MIDPOINT \
  --entry-max-wait-bars 5 \
  --cost-profile conservative_crypto_1m \
  --allowed-pattern-statuses VALID,WEAK \
  --enable-regime-stratification
```

For code-driven studies, use `run_fvg_retest_v2_research_protocol(...)` to emit one JSON/markdown evidence package containing:

- parameter declaration and config hashes,
- dataset identity hash,
- full parameter-grid rows for all attempted variants,
- per-variant WFO folds and aggregate metrics,
- timing diagnostics including MFE/MAE when available,
- weakness labels for no-fill retests, poor follow-through, trend overblocking, liquidity scarcity, cost drag, and drawdown pressure,
- research-only promotion/rejection summary.

## Required Reporting Dimensions

Reports must preserve aggregate evidence by:

- multi-timeframe trend alignment,
- Fibonacci confluence,
- liquidity-target availability,
- entry trigger,
- stop mode,
- market regime,
- session,
- cost profile.

Sparse windows are warnings, not a reason to delete a fold.

## Promotion And Rejection Rules

Promotion is never automatic. Preliminary WFO evidence can only mark a candidate as `RESEARCH_CANDIDATE_NEEDS_LOCKED_HOLDOUT`; it cannot approve paper or live trading.

Reject or retest the research cycle when any of these dominate:

- repeated OOS failures,
- no-fill retest dominance,
- negative expectancy after realistic costs,
- trend filter overblocking,
- liquidity target scarcity,
- adverse excursion dominating MFE,
- drawdown pressure,
- insufficient folds.

Minimum preliminary thresholds are encoded in `FvgRetestV2ResearchProtocolConfig`, but locked holdout confirmation and owner review are still mandatory before any future paper-only task.
