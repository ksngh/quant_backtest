# Task 293: Daily Report Image Asset Rules V2

# Goal

Update the daily report data and image-generation rules to match the new report artifact format supplied by the owner.

The new format is centered on a daily report folder with an `images/` subfolder, four required fixed images, optional numbered variant images, and an explicit image-plan step before images are generated.

# Source Requirement

Owner request:

```text
산출물이 바뀌었고, 그에따라 너가 저장해야할 데이터 양식이 조금 바뀌었어.
내가 이미지 생성 규칙을 줄테니까 이걸 반영해서 이미지 생성 rule을 바꿔줘.
```

Clean requirement:

- Replace the current daily-report image rule with the owner-provided image asset rule.
- Daily report artifacts should use:

```text
daily_report/YYYY-MM-DD-[strategy-slug]/
  report-ko.md
  report-en.md
  images/
```

- Required fixed images must be generated under `./images/`:

```text
summary_equity_curve.png
cost_impact.png
representative_win_trade.png
representative_loss_trade.png
```

- `summary_equity_curve.png` must combine equity curve and drawdown in one image.
- Separate `drawdown_curve.png` must not be generated by default.
- Cost impact images must compare transaction-cost effects and must not use the phrase `cost stress` in chart titles or labels.
- Representative trade images must be candlestick charts when candle data is available.
- Variant images must follow the numbered filename rules:

```text
10_equity_curve_[number]_[timeframe]_[period-slug]_[variant-slug].png
20_cost_impact_[number]_[timeframe]_[period-slug]_[variant-slug].png
30_win_trade_[number]_[timeframe]_[period-slug]_[variant-slug].png
40_loss_trade_[number]_[timeframe]_[period-slug]_[variant-slug].png
```

- Image generation must first produce an internally consistent image plan.
- The rule documents must tell future agents to create images only under the report folder's `images/` directory and reference them as `./images/[filename].png`.

# Requirements

## Storage Rule Requirements

- New report artifacts must be stored under:

```text
daily_report/YYYY-MM-DD-[strategy-slug]/
```

- Reports and images must use:

```text
daily_report/YYYY-MM-DD-[strategy-slug]/
  report-ko.md
  report-en.md
  payload.json
  image_plan.md or image_plan.json
  images/
```

- All generated images must be under:

```text
daily_report/YYYY-MM-DD-[strategy-slug]/images/
```

- Markdown references must use:

```text
./images/[filename].png
```

## Fixed Image Requirements

Every daily report must plan and generate:

```text
summary_equity_curve.png
cost_impact.png
representative_win_trade.png
representative_loss_trade.png
```

`summary_equity_curve.png`:

- Must use a two-panel layout.
- Upper panel: equity curve.
- Lower panel: drawdown or underwater curve.
- Must annotate strategy name, symbol, timeframe, period, total return, max drawdown, total trades, win rate, and expectancy when available.
- Must be readable in a blog post.

`cost_impact.png`:

- Must use cost-level equity curves when available:
  - no cost equity.
  - fee only equity.
  - fee + spread equity.
  - fee + spread + slippage equity.
- Must fall back to aggregate values when only totals are available:
  - gross PnL.
  - fee.
  - spread.
  - slippage.
  - net PnL.
- Must annotate total fee, total spread, total slippage, total transaction cost, gross PnL, net PnL, and final return after costs when available.
- Must not use `cost stress` in chart titles or labels.

`representative_win_trade.png` and `representative_loss_trade.png`:

- Must use candlestick charts when OHLC candle data is available.
- Must show candles around the trade window.
- Must show entry marker and exit marker.
- Must show stop line, target line, pattern zone, or signal zone when available.
- Must show side, entry price, exit price, entry time, exit time, net PnL, and exit reason when available.
- Winning trade selection should prefer `representative_trades.best_trade`.
- Losing trade selection should prefer `representative_trades.worst_trade`.

## Variant Image Requirements

- If multiple variants are compared, generate additional numbered images.
- Variant dimensions include:
  - timeframe.
  - test period.
  - symbol.
  - strategy variant.
  - entry condition.
  - exit condition.
  - lookback.
  - holding period.
  - threshold.
  - stop/target logic.
  - cost assumption.
  - market regime.
- Do not overwrite fixed images.

Variant equity filenames:

```text
10_equity_curve_[number]_[timeframe]_[period-slug]_[variant-slug].png
```

Variant cost filenames:

```text
20_cost_impact_[number]_[timeframe]_[period-slug]_[variant-slug].png
```

Optional variant trade filenames:

```text
30_win_trade_[number]_[timeframe]_[period-slug]_[variant-slug].png
40_loss_trade_[number]_[timeframe]_[period-slug]_[variant-slug].png
```

Slug rules:

- `number`: two digits, e.g. `01`.
- `timeframe`: `1m`, `5m`, `15m`, `1h`, `4h`, `1d`.
- `period-slug`: `YYYYMMDD_YYYYMMDD`.
- `variant-slug`: lowercase letters, numbers, and underscores only.

## Image Plan Requirements

Before generating images, the image-generation workflow must output an image plan with:

- Fixed image list.
- Each fixed image source, purpose, and report section.
- Variant image table:
  - No.
  - Filename.
  - Timeframe.
  - Period.
  - Variant.
  - Reason.

Images must not be generated until the image plan is internally consistent.

## Final Check Requirements

The workflow must check:

- `summary_equity_curve.png` exists.
- `cost_impact.png` exists.
- `representative_win_trade.png` exists.
- `representative_loss_trade.png` exists.
- Every equity curve image includes drawdown in the same image.
- No separate `drawdown_curve.png` was generated unless explicitly requested.
- All variant equity filenames start with `10_equity_curve_`.
- All variant cost filenames start with `20_cost_impact_`.
- Every image path is under `./images/`.
- Markdown report can reference every generated image.
