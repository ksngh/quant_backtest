# Task 249: FVG V2 Channel Geometry Persistence And API

# Goal

Persist and expose FVG v2 channel geometry, retest, and boundary-exit metadata so saved backtest runs can be inspected without rerunning strategy logic.

# Source Requirement

Owner requirement:

- The system should draw the channel lines and show them in the frontend.
- The frontend needs the line geometry generated by the algorithm.
- Trade-level inspection should make clear which line was used for entry, stop, and exit.

# Extracted Roles

- Owner role:
  - Saved-run diagnostics and API contract owner.
- Supporting roles:
  - Persistence adapter role: owns serializing channel metadata into saved run/trade/graph records.
  - Backend API role: owns read-only response shape and redaction-safe exposure.
  - Contract/documentation role: owns API contract updates.
  - Test role: owns persistence/API metadata coverage.
- Forbidden roles:
  - Do not implement frontend drawing here.
  - Do not change channel detection or trading logic here except to pass already-created metadata through.
  - Do not add backtest execution endpoints.
  - Do not add live trading, order endpoints, account endpoints, credentials, or real exchange calls.

# Context

Tasks 247 and 248 should produce channel geometry and trade metadata. Existing persistence/API paths already carry rich metadata for trades, graph points, diagnostics, and research reports. This task should make the channel line data durable and visible through read-only saved-run API responses.

# Scope

- Identify the metadata source from Task 247/248.
- Ensure saved run/trade metadata includes:
  - channel geometry,
  - lower and upper line parameters,
  - anchor candle indices/timestamps/prices,
  - upper-touch candle index/timestamp/price,
  - entry retest touch and confirmation,
  - boundary stop/target prices,
  - exit boundary and reason.
- Expose metadata in `GET /api/backtest-runs/{id}` without rerunning backtests.
- Update `docs/api/API_CONTRACT.md` with read-only channel metadata fields.
- Update backend research-report diagnostics if appropriate.
- Preserve legacy saved-run behavior when channel metadata is absent.

# Out of Scope

- Do not add frontend overlay rendering.
- Do not create database migrations unless existing JSON metadata persistence cannot carry the accepted field set.
- Do not change cost/slippage formulas.
- Do not add strategy execution endpoints.

# Requirements

- Channel metadata must survive execution serialization and persistence.
- Backend API must return channel metadata for enriched runs and safe fallbacks for legacy runs.
- Response shape must remain backward compatible.
- Sensitive-data redaction must continue to apply.
- No strategy/backtest recomputation may occur in API request handling.
